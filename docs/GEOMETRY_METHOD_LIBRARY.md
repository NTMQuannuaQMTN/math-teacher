# Geometry method library

Source of truth: [`shared/src/proof/methods.ts`](../shared/src/proof/methods.ts). The tables below are generated by
`npx tsx worker/scripts/method-library-doc.ts`; a test checks that every method the search uses is registered and
marked as used.

Each method has:
- a Vietnamese name, which is shown to the student as the step's reason;
- a category, grade and difficulty (1 = basic grade 7–8, 2 = grade 9, 3 = entrance-exam standard, 4–5 = chuyên
  configurations);
- whether it is allowed (inside the grade-9 knowledge base; "advanced" = only when the problem calls for it);
- the fact types it needs and produces, which the verifier checks;
- its prerequisites in words, and the common errors that the explanation and hints guard against.

Methods marked "used by the search" are applied by the planner. Several angle methods (vertical angles, linear pairs,
alternate/corresponding angles, angle sum, inscribed angles, central angles of a regular configuration) are not
separate rules: they hold automatically in the angle algebra, so one `ANGLE_CHASE` step covers them and its
explanation names which kinds of facts it used. Methods not used by the search are documented for the solver's prompt
and for grading. The five that are not allowed (inversion, projective geometry, trigonometric laws, coordinates and
vectors as a proof method) are rejected by the verifier.

**Selection.** For each goal type the search tries the cheapest methods first (`methodsFor` sorts by difficulty).
Iterative deepening prefers the shallowest proof. Premise minimisation keeps the cheapest set of facts a step needs.
